# 设计与开发教程

## 先组织阅读顺序，再画装饰

首页首先回答“这里是什么”，然后按发布时间展示文章与碎碎念混合信息流：文章卡片显示标题和摘要，碎碎念卡片直接显示正文。侧栏只有个人角落和标签，不再把文章作为主栏、把短动态放在侧栏。手机改为单列，不依赖横向滚动。独立碎碎念列表继续用日期和圆点表达时间关系，不增加点赞等尚未实现的按钮。

视觉选型比较保存在 [设计决策](08-decisions.md)。最终采用低饱和雾蓝而不是更温暖的陶土色：它更适合代码、表格和技术笔记长时间阅读。原创插画负责二次元气氛，页面结构仍由内容决定。文字使用系统字体，不依赖第三方字体网络请求；标题尝试系统中的中文衬线字体，没有时自然回退。

## 第一步：读懂 Astro 文件

以 `src/components/PostCard.astro` 为例，顶部 `---` 内是构建时执行的 TypeScript：导入类型、接收 entry、调用日期和链接辅助函数。下方是 HTML 模板，花括号插入数据。默认不会把这些构建逻辑发送给浏览器。

页面 `posts/index.astro` 调用 `published()` 获得已发布文章，将当前页的 entry 交给 `PostList` 和 `PostCard`。这里可以学习三个边界：数据读取放页面/共用函数，数据展示放组件，页面外壳放 layout。

练习：在 PostCard 标题下增加一行日期说明。只改组件后，首页、文章列表、标签列表会同时变化；这就是复用组件的价值。不要把相同 HTML 复制到三个页面。

## 第二步：理解动态路由

打开 `src/pages/posts/[...id].astro`。文件名不是文章的实际 URL；getStaticPaths() 枚举内容 id，构建时逐一渲染。`render(entry)` 提供 Content 和 headings。目录直接使用 headings.slug 作为锚点，避免自行用标题猜测 id。

短动态走类似路由，但 MomentCard 在列表上也渲染全文。没有标题时页面使用隐藏的 h1 给辅助技术提供文档名称，读者看到日期和正文即可。

练习：在文章底部增加一段统一的阅读提示。放在详情模板，避免写进每篇 Markdown。

## 第三步：改样式时先改语义变量

global.css 中 `--bg` 是页面背景，`--surface` 是独立表面，`--text` 是主要文字，`--muted` 是次要文字，`--accent` 是交互强调色。暗色模式重新定义这些变量，而不是为每个组件复制整套 CSS。

比如想让链接偏紫，可同时调整浅色/暗色的 accent；不要只改一个按钮。确保文字与背景仍容易辨认。暗色主题是手动持久化偏好优先，未选择时跟随系统。代码块使用 Shiki 的双主题 token，正文和代码一起切换。

布局用 CSS Grid 和 Flex。900px 以下重排导航与目录，640px 以下首页改为单列。`minmax(0, 1fr)` 和 `min-width:0` 允许列缩小；代码、表格、公式在自己的容器内横向滚动，避免撑宽整个页面。

## 第四步：搜索为什么无需服务器

`search-index.json.ts` 在构建时把已发布内容转成一个 JSON 文件。`search.astro` 的浏览器脚本在输入关键词时读取它。匹配逻辑将中文、英文和全角字符做 NFKC 规范化，然后对标题、正文和标签执行包含匹配。

查询状态保留在 URL 的 q 参数，复制搜索地址可分享。请求编号防止旧请求回来覆盖新查询；网络失败显示可恢复提示。结果使用 DOM 的 textContent，查询中的尖括号不会变成可执行 HTML。

练习：先在 Markdown 加一个只出现在正文中的关键词，构建后搜索它。这能验证你理解了“索引在构建时生成”，而非误以为网站实时读取本地文件。

## 第五步：理解资源路径

组件中的站内地址调用 `url('posts/')`。它读取 Astro 的 BASE_URL。Markdown 是另一条渲染路径，所以需要 remark 插件添加同样前缀。CSS、脚本由构建工具管理，不能把本机 D 盘路径写进页面。

练习：按部署指南设置 BLOG_BASE 为 `/astro-blog`，构建并运行 verify。这个实验会暴露那些只在根路径下有效的写法。

## 可访问性与渐进增强

- 页面使用 header/nav/main/footer，main 有可跳转入口，键盘 Tab 可以到达跳到正文链接。
- 图标按钮提供中文 aria-label；装饰图标 aria-hidden，插画有有意义的 alt。
- 当前导航使用 aria-current；搜索反馈用 role=status，不强制抢焦点。
- 保留可见键盘焦点和系统减少动画偏好。
- 禁用 JavaScript 后仍能读文章、动态、目录和导航；搜索说明其需要脚本，主题按钮隐藏。

测试能证明部分行为，不能替代所有辅助技术或真实用户反馈。进一步改版时也应实际用键盘和手机走一遍主要流程。
