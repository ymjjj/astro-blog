# 恢复中心、备份与图片管理

双击 `start-studio.cmd`，打开 <http://127.0.0.1:4323>。这些功能只在本机运行，公开博客仍只部署 `dist`。

## 找回或整理恢复副本

有恢复副本时，写作台顶部显示“找回未完成的编辑”。可以按标题、正文、所属内容搜索，查看时间、内容 ID 和占用空间。服务器副本显示实际文件字节数，尚未同步的浏览器副本按 UTF-8 估算。

- **预览副本**：展开元数据和全文，以纯文本呈现，不执行其中的 HTML。
- **恢复编辑**：载入编辑器，沿用上轮的版本冲突保护；找回后仍需保存，不代表上线。
- **预览清理**：先把当前浏览器的恢复副本同步到本机，生成精确文件清单。审查后勾选确认，再点击“确认执行清单”。
- **回收站 → 预览撤销**：确认撤销清单后找回资料。如果原位置后来有了新修改，会拒绝覆盖，需要先备份并手动合并。

其他浏览器或其他端口还没同步的文字，当前工作台无法读取。整理之前应在相关窗口完成保存或恢复副本同步。清理不是永久删除；本轮没有自动永久清空回收站的功能。

兼容接口 `discard` 现在也把单个恢复副本归档到回收站。正常保存后的副本收尾使用这个入口，所以回收站也可能出现自动保存产生的归档。正式文章与历史不受这类收尾影响。

## 图片管理

在“资料管理”点击“管理图片”，可按文件名或引用者搜索，筛选“没有已知引用”，并手动刷新。

每张图显示路径、文件大小、尺寸、引用位置和清理状态。点击“预览图片”生成小尺寸 WebP 缩略图；不会把源目录公开给浏览器。SVG 作为矢量资源列出和备份，但不在本地管理页生成缩略图。

引用位置分为：

1. 正文：当前文章和碎碎念，包含草稿。
2. 历史：旧正文仍需使用的图片。
3. 恢复副本：尚未完成的编辑。
4. 回收站：撤销清理或替换时可能需要的图片。
5. 站点源码：组件、样式、配置和其他静态引用。

只有 `src/assets/uploads/<哈希>.webp` 中的受管理图片才允许清理。站点插画、头像、手工放入的资源只展示，不提供自动清理。导入或恢复不足 24 小时的图片也受保护，避免尚未插入正文就被误删。

引用分析采用保守的文件名匹配，兼容百分号编码与大小写；即便文件名只出现在文字说明中，也可能被当作引用而保留。任意程序动态拼接出来的路径无法完全静态推断，所以“没有已知引用”不等于绝对无人使用。执行前仍需查看清单；误清理可撤销。不要绕过保护手工删除历史仍需的图片。

## 生成、下载与导入备份

进入“备份与恢复”，点击“生成备份”。当前浏览器可见的恢复副本会先同步到本机；如果本机副本已被其他窗口修改，先处理冲突，不能强行覆盖。

备份白名单包括：

| 范围                                       | 内容                                           |
| ------------------------------------------ | ---------------------------------------------- |
| `src/content/posts`、`src/content/moments` | Markdown 正文与元数据                          |
| `src/assets`、`public`、`assets/source`    | PNG、JPEG、WebP、GIF、AVIF、SVG 图片，包括原稿 |
| `.blog/history`                            | 内容修改历史                                   |
| `.blog/recovery`                           | 已同步的恢复副本                               |

备份**不包含**网站代码、依赖、`.env`、凭据、发布配置、请求日志、计划文件、回收站及其他备份包。它是内容资料备份，不是整个项目的系统镜像。若回收站内有需要带走的内容，先撤销找回，再导出；网站代码和配置请另行备份。

生成后点击“校验与查看清单”，可以确认文件路径、大小、SHA-256。点击“下载备份”，把 `.blogbackup.gz` 文件保存到自己的其他磁盘或备份设备。本机 `.blog/backups` 中多留一份不能替代异地备份。

换电脑时先准备同版本项目及依赖，启动工作台，再通过文件选择器导入备份包。导入会逐项校验，**不会立即恢复**。备份使用本站专用 gzip JSON 格式，不是任意 ZIP；压缩包和源资料各上限 64 MiB，最多 10,000 个文件，解压 JSON 上限 128 MiB。超出时会明确拒绝，不生成不完整包。

备份可能含草稿私有内容，没有加密。请存放在自己的受保护位置，不要上传到公开仓库或放入网站 `public` 目录。哈希用于检验完整性，不是来源签名；只导入可信的本站备份。

## 预览并恢复备份

1. 在选中的备份行点击“预览恢复”。
2. 查看新增、替换的路径和执行前后的字节数；展开文本文件查看前后片段（每侧最多 2,000 字符）。完整文本可通过 CLI 的 `backupcheck` 加 `path` 读取。
3. 确认清单符合预期，先保存当前编辑，再勾选确认并执行。若保存引发新修改，需要重新生成计划。
4. 恢复只合并备份中的文件，不删除当前项目中备份之外的新文件。元数据包括当时的草稿/发布标记，但不会执行提交、推送或线上发布。
5. 被替换文件会保留撤销资料。完成后可在回收站预览撤销，回到执行前的版本。

计划包含当时的文件指纹和引用资料指纹。预览之后只要相关资料有变化，返回 `PLAN_STALE`，要求重新审查。不能复用旧清单并自动换哈希来强行执行。

批量修改不是文件系统的多文件原子事务。系统先保存撤销资料，再逐文件核对、写入和记录进度；中途失败或进程退出可能留下部分完成状态。回收站显示“执行失败”或“执行中或已中断”，请确认没有任务还在运行，再预览撤销。撤销遇到后续编辑也会拒绝覆盖，不会为“回滚成功”而丢掉新资料。

## CLI 与 MCP 操作示例

两者共用 `tools/blog/core.mjs` 和同一套参数、幂等与版本规则。CLI 输出单个 JSON；下面各段 JSON 保存到 `request.json` 后执行：

```powershell
node tools/blog/cli.mjs plan --input request.json --json
```

根据操作替换 `plan`。MCP 对应 `blog_<操作名>`，例如 `blog_backupcheck`。

| 操作           | 参数                                                  | 结果                                          |
| -------------- | ----------------------------------------------------- | --------------------------------------------- |
| `recovery`     | 可选 `query`、`summary:true`、`sessionId`             | 搜索或读取恢复副本；summary 用于列表字节数    |
| `assets`       | 可选 `query`、`unused`                                | 图片大小、尺寸、引用和清理资格                |
| `asset`        | `path`                                                | 安全栅格缩略图 dataUrl                        |
| `backups`      | `{}`                                                  | 本机备份列表                                  |
| `backup`       | `requestId`                                           | 生成备份，返回 backupId、项目内路径及清单哈希 |
| `backupimport` | `file` 或 `base64` 二选一，`requestId`                | 校验并暂存备份，返回 backupId                 |
| `backupcheck`  | `backupId`，可选 `path`                               | 全包校验；指定 path 时读取备份中的完整文本    |
| `plan`         | `kind`、相应目标、`requestId`                         | 只生成审查清单和 expectedPlan                 |
| `apply`        | `planId`、`expectedPlan`、`confirm:true`、`requestId` | 执行已确认清单，返回 transactionId            |
| `trash`        | `{}`                                                  | 回收站事务、状态及涉及路径                    |

创建备份：

```json
{ "requestId": "f811f5e4-dc40-45cd-932d-84a0fe292f2e" }
```

导入本地备份（CLI/MCP）：

```json
{
  "file": "D:\\backups\\my-blog.blogbackup.gz",
  "requestId": "434db7cd-3b51-49c3-b05c-f93ebcce4b57"
}
```

预览恢复（将 backupId 换成实际返回的 UUID）：

```json
{
  "kind": "restore",
  "backupId": "41da9f3e-9134-4774-9630-cb0f4846b732",
  "requestId": "d8f7f8d7-b8a6-4c05-bc3a-282ccdc0c455"
}
```

预览清理，只传已经检查过的路径；可以一次选择多个副本或合格图片：

```json
{
  "kind": "cleanup",
  "paths": [".blog/recovery/4337de48-8aa9-4897-9ffb-48624c68cf07.json"],
  "requestId": "26367120-cf91-4c9d-a172-6f799c176125"
}
```

审查后执行：

```json
{
  "planId": "用 plan 返回的真实 UUID 替换",
  "expectedPlan": "用 plan 返回的 64 位哈希替换",
  "confirm": true,
  "requestId": "e3beecb5-7428-480a-931a-b76c72786140"
}
```

预览撤销：

```json
{
  "kind": "undo",
  "transactionId": "用 apply 或 trash 返回的真实 UUID 替换",
  "requestId": "75643aa2-7d64-45d4-b8de-b97aa19e507e"
}
```

每次新操作生成新的 requestId。重试同一请求保持原 ID 和全部参数；尤其 apply 已成功但响应丢失时，重复原请求会返回原结果，不能另起请求盲目再次清理。

### 给 Hermes 的执行约定

> 检查博客资料占用，列出没有已知引用且已过保护期的图片，说明引用检查范围。生成清理计划，把完整清单交给我检查；在我确认前不要 apply。

> 导出博客内容备份并校验，告诉我实际文件位置和大小，不上传到任何远程服务。

> 读取我指定的备份，先 backupcheck 再 plan restore，说明新增和替换哪些文件。经我确认后 apply；失败时报告 transactionId 和已知状态，不强行覆盖新修改。

通用 CLI/MCP 已提供，Hermes 具体安装的实机配置仍需使用其实际版本联调。测试使用 MCP SDK 客户端，不代表已经连接你的 Hermes。

## 开发设计与故障排查

`maintenance.mjs` 负责备份、引用图、操作计划与事务；`maintenance.js` 是仅本机工作台的展示模块。新增工具通过统一 contracts 自动暴露给 CLI/MCP，界面没有独立的修改规则。

备份文件逐一保存 path、bytes、SHA-256 与 base64，再计算清单哈希并 gzip 压缩。导入拒绝路径穿越、Windows 保留文件名/数据流、大小写重复路径、范围外的配置或代码文件、被篡改内容、历史校验错误及错名的受管理图片。所有目标再经过实际路径/符号链接检查。

计划保存在 `.blog/plans`，修改前资料保存在 `.blog/trash`。apply 的期望哈希必须与实际清单一致，正式变更使用项目写锁协调工作台、CLI 和 MCP。第三方直接写文件不遵守这个锁，逐文件检查只能缩小竞争窗口，不能提供对任意外部写入的绝对锁定。需要强一致协作时让 Hermes 使用共用接口。

| 错误                 | 下一步                                                     |
| -------------------- | ---------------------------------------------------------- |
| `PLAN_STALE`         | 文件、引用或撤销目标已变化；重新读取并生成计划             |
| `ASSET_PROTECTED`    | 查看引用位置、是否受管理及24小时保护期；不要绕过检查       |
| `INVALID_BACKUP`     | 包损坏、格式不支持、哈希或路径校验失败；使用可信的原始备份 |
| `BACKUP_TOO_LARGE`   | 超过文件数或体积上限；先分开归档，不会自动导出残缺内容     |
| `TRANSACTION_FAILED` | 根据返回 transactionId 查看回收站；核对部分执行后预览撤销  |
| `BUSY`               | 其他写入正在进行，等待完成后重试；不要自动删除锁           |
| 浏览器与本机副本不同 | 先找回并合并冲突，再同步、备份或清理                       |

回收站、计划、备份都不会自动永久删除，长期使用需要自行安排资料归档。不要为节省空间直接删除唯一撤销资料。当前备份也不含仅浏览器保存而尚未同步的内容，界面会先同步当前浏览器能读取的副本。
