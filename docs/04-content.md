# 内容规范

## 文件名就是稳定链接

文章放在 `src/content/posts/`，动态放在 `src/content/moments/`。使用小写英文、数字和连字符，例如 `my-first-note.md`，也允许 `learning/first-note.md` 这样的子目录。文件名决定 URL；标题可以随时改，已经分享出去的文件名尽量不要改。

`posts/my-first-note.md` 对应 `/posts/my-first-note/`。没有 title 的动态仍然用文件名获得独立地址。中文用于标题和标签即可，不用于本期文件名。不要设置额外 slug 字段，当前加载器以相对文件路径作为唯一标识。

## Frontmatter 字段

文件开头两个 `---` 中间是 YAML 元数据，不属于正文。

| 字段        | 文章       | 动态      | 说明                                                                                                                                           |
| ----------- | ---------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| title       | 非空，必填 | 可省略    | 无标题动态在归档和搜索中显示「碎碎念 · 日期」                                                                                                  |
| description | 非空，必填 | 不需要    | 文章列表和 SEO 摘要；动态从正文提取摘要                                                                                                        |
| date        | 必填       | 必填      | 带时区的 ISO 时间，建议加引号                                                                                                                  |
| updated     | 可省略     | 不适用    | 文章更新时间：带时区的 ISO 时间，不能早于 date；由作者手动维护，不读取文件 mtime。文章列表、详情、SEO 和 sitemap 使用此值，内容排序仍按 date。 |
| tags        | 可省略     | 可省略    | 字符串数组，自动去掉重复项与两端空格                                                                                                           |
| draft       | 默认 true  | 默认 true | 必须显式设置布尔值 false 才发布                                                                                                                |

```yaml
---
title: '我的第一篇笔记'
description: '用几句话说明这一篇写了什么。'
date: '2026-09-26T15:00:00+08:00'
tags: [学习笔记, Astro]
draft: false
---
```

日期按时间戳倒序排列，同时间按 id 排序。显示和年份归档固定使用配置时区。第一版不实现定时发布，未来日期只影响排序；不想公开就保留 draft:true。YAML 的 `false` 不要写成字符串 `"false"`。

## 正文

页面已经提供一级标题，文章正文从 `##` 开始。目录提取二级、三级标题。支持标准 Markdown、GFM 表格、任务列表、代码围栏、引用以及公式。代码围栏注明语言，例如 ts、js、css。公式用 `$x^2$` 或独立 `$$` 块。

文章示例 `static-garden.md` 集中展示标题、代码、图片、表格、公式。动态建议一两段，可附配图；网站不强制长度。

## 图片和链接

公开图片放入 `public/media/`，引用时省略 public：

```markdown
![描述图片内容](/media/window-notes.webp)
[浏览全部文章](/posts/)
```

部署子路径由插件自动添加，不要在 Markdown 中硬写 `/astro-blog/`。外部链接使用完整 https 地址。原始 HTML 的 `<img src>`、`<a href>` 不会经过 Markdown 路径插件，优先用上述标准语法。

草稿专用图片放在 `src/assets/`，用相对路径，例如从 posts 文件夹引用 `../../assets/my-diagram.webp`。dev 会渲染草稿正文并解析其图片依赖，生产构建只处理已发布正文。公开使用过的共享图片自然仍然是公开资源。

**public 内的一切都会公开复制，不能存私密资料。** 网站不发布草稿不代表 Git 仓库会隐藏草稿；公开仓库中的所有已提交文件都能被读取。

建议图片先压缩为 WebP，正文大图控制在适当尺寸。alt 描述内容，不用只写“图片”。源图可存 assets/source，它不参与网站部署。本站首页插画已压缩到约 115 KiB。

## 草稿策略

`npm run dev` 在 `127.0.0.1` 提供本地草稿预览。导航中的「草稿箱」`/drafts/` 列出草稿；文章和动态（包括无标题动态）都可从草稿箱直接打开预览，详情页会显示明显的草稿标记。不要将开发服务暴露到公网。

首页、文章和动态列表、标签、归档、搜索、RSS 与 sitemap 仍只展示已发布内容。生产构建以及 `npm run preview`（预览 `dist`）不包含草稿。生产构建使用 `astro build --force` 清理内容缓存，防止曾经发布的资源因缓存残留。
