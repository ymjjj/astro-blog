# 设计决策

## 静态生成

选择 Astro 静态输出而不是运行时后端。所有内容在构建时读取，部署只需要 dist 文件。写作后需要重新构建，但读者不依赖数据库、登录或常驻进程。

## 两种内容，同一个发布出口

文章和动态使用独立集合。文章标题必填；动态标题可选，时间线直接显示全文。自定义加载器在正文渲染前排除草稿，所有公开页面、搜索、RSS、站点地图再通过统一的已发布内容函数读取。原因是实际测试发现默认 glob 的预渲染会把未公开草稿的图片带入 dist，单纯过滤页面查询不够。构建使用 --force 清除历史内容缓存，避免从发布改回草稿后的附件残留。

草稿源文件仍属于本地和 Git 仓库中的数据，不等于加密。public 目录全部公开，只放明确公开的资源；草稿专用图片存放在 src 内，可在 dev 本地预览，生产模式仅在发布后被引用。

## 视觉对比与选择

| 方向             | 背景 / 强调色               | 气质                         | 取舍                                 |
| ---------------- | --------------------------- | ---------------------------- | ------------------------------------ |
| 清爽浅色（采用） | 纸白 #f7f9fc / 雾蓝 #466ba6 | 像窗边的笔记本，适合技术笔记 | 插画提供温度，正文减少装饰           |
| 温暖手帐         | 米白 #faf6ef / 陶土 #a46d50 | 日常感更强                   | 保留为设计参考，不增加第二套主题系统 |

首页采用大留白、衬线中文标题和紧凑文字导航。当前主页按时间混排文章摘要与碎碎念正文；侧栏放个人角落和标签。小屏按阅读顺序纵向排列。明暗主题共用语义色变量，避免到处写死颜色。

## 工程边界

无需 React 等客户端框架。搜索、主题和第二阶段阅读工具使用少量原生脚本。站点配置集中，路径统一加 base。未知姓名与经历使用明确占位信息。Markdown 文件仍是唯一内容源；本地写作台、CLI 与 MCP 已实现，并通过共用内容核心操作同一套文件和校验规则。操作说明见[写作台指南](13-writing-and-agents.md)，工具实现与边界见[开发工作坊](14-development-workshop.md)。

## 第二阶段

草稿模式以 Astro 实际运行命令为准，配置钩子将 `command === 'dev'` 写成构建常量。没有允许生产发布草稿的环境变量开关，`--mode development` 也不能开启它。详情通过 readable() 获得本地可读内容；首页和所有公共出口继续只用 published()。草稿标签是不可点击的标记，不为草稿单独生成公开标签页。

更新时间使用作者显式填写的 updated，不猜文件 mtime 或 Git 历史，避免跨设备和构建过程产生误导。校验要求其不早于 date，排序仍按首次发布日期。

图片层选择原生 dialog，提供焦点恢复和 Escape 关闭；代码复制使用 Clipboard API，失败后选中原文供手动复制。目录按标题位置选中当前章节，仅修改 aria-current，不在滚动时不断改写 URL。详细实现见 [第二阶段教程](10-phase-two.md)。

## 后续实现的决策

- **共用内容核心：** 写作台、CLI 和 MCP 共享同一组操作契约、revision 冲突检查、requestId 幂等和内容校验，避免每个入口各自维护写入规则。
- **本地工作台与 Agent 接口：** 写作台只监听回环地址；MCP 提供通用 stdio 接口。Hermes 专用配置依赖实际使用的版本，尚未确认或宣称原生集成。
- **萌系插画：** 通过原创蓝发小作家和白猫插画增加页面温度，插画源文件与生成说明见[图片来源](assets/image-generation.md)。正文仍保持适合阅读的字号和对比度。
- **混排与静态分页：** 首页按发布时间合并文章和碎碎念，分别使用文章摘要卡片与碎碎念全文卡片；首页及两个独立列表每页 6 条，由构建生成后续路由，不依赖线上翻页服务。
- **发布权限：** 发布默认只做隔离构建演练。真实远程发布须由用户确认目标并完成本机配置；流程实现不等于已授权或已上线。
