## 先把入口整理好

![黑白漫画：白猫枕着笔记本休息](/media/manga-cat.webp)

静态博客可以看作一座由文件组成的小花园：文章是内容，导航是路径，构建工具则负责把源文件整理成浏览器能够读取的页面。开始写作前，先约定文章放在哪里、图片如何命名、草稿怎样标记。稳定的目录习惯会减少寻找文件的时间，也让以后换主题或迁移平台更轻松。这里的“花园”是一种帮助理解的比喻，实际项目仍要依照自己的内容模型来组织。

## 用 Markdown 写清楚内容

Markdown 适合先专注于文字，再逐步补充结构。标题要按层级排列，段落一次说明一个重点，链接的文字也应说清目标。文章开头的 frontmatter 保存标题、摘要、日期和标签等信息；这些字段能帮助页面显示文章，也能支持归档与筛选。日期采用带时区的 ISO 格式，可以减少不同设备显示时间时的歧义。

### 用类型检查元数据

下面的 TypeScript 片段只是示例，展示数据形状如何表达清楚：

```ts
type PostMeta = {
  title: string;
  date: string;
  tags: string[];
  draft: boolean;
};

const post: PostMeta = {
  title: '小站写作流程',
  date: '2026-09-26T12:00:00+08:00',
  tags: ['Astro', '写作'],
  draft: false,
};
```

整理新文章时，可以依次完成这些步骤：

- 先写一个能概括主题的标题与摘要。
- 用小节拆分内容，让读者能快速定位。
- 发布前检查日期、标签和草稿状态。

| 字段  | 用途       | 检查方式     |
| ----- | ---------- | ------------ |
| title | 页面标题   | 能否概括主题 |
| date  | 排序与显示 | 是否包含时区 |
| tags  | 主题归档   | 命名是否一致 |

> 好的整理方式不会替代写作；它让已经写下的想法更容易被再次找到。

若把可读性粗略记作 $R$，结构清晰度记作 $C$，内容完整度记作 $N$，无关装饰记作 $D$，可用一个简单模型提醒自己：

$$
R = C + N - D
$$

这个公式不是评分标准，只是提示：发布流程的每一步都应帮助内容更容易理解。先让目录、元数据和正文各司其职，小站就有了持续生长的基础。
